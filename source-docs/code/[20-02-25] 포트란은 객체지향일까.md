포트란은 객체지향일까?
포트란이라 하면 옛날 언어라고 생각하기 쉽지만, 해를 거듭할수록 업그레이드되었다. 특히 2003버젼부터는 클래스와 상속 등을 지원하는 객체지향 프로그래밍 언어라고 할 수 있다.
포트란과 함수 오버로딩
함수 오버로딩이란 같은 이름의 서브프로그램이 인자에 따라 다른 기능을 하는 것을 말한다. 객체지향 언어에서의 ‘다형성’과 관련된 개념이고, 포트란에서는 90버전에 도입된 ‘interface’문을 이용하여 적용 가능하다. 오버로딩이란 같은 이름에 여러 의미를 부여한다는 뜻이다.
포트란의 객체지향적 특징
1) data abstraction : user-defined types
2) data hiding : private and public attributes
3) encapsulation : modules and data hiding facilities
4) inheritance and extensibility : generic procedures
5) polymorphism : generic overloading
6) reusability : modules
USE stack, ONLY : pos, local_pop=> pop
모듈 stack속의 pos와 pop만 사용 가능하고, pop의 경우 local_pop로 이름이 다시 만들어진다.
모든 모듈들은 그것을 사용하는 프로그램 단위보다 먼저 컴파일되어야 한다.
특정 모듈을 사용할 때, use 모듈이름은 제일 앞쪽에 선언된다. 즉 그 모듈을 사용하는 서브루틴에서 모든 변수들 보다 앞서서 선언되고 결국 implicit none 보다 앞서서 그 바로 윗줄에서 정의된다. 즉 컴파일할 때 먼저 불러져서 컴파일이 될 수 밖에 없다.
Implicit none : 어떠한 것도 묵시적이지 않다고 선언하는 것이다. 즉, 모든 변수들이 구체적인 형을 선언해 주어야 한다는 것이다. 더욱이, 모듈 개념을 사용할 때는 꼭 있어야한다는 생각을 한다. 왜냐하면 use를 사용하는 경우 사용하는 모듈 속에 변수들이 존재하는지를 컴파일하는 단계에서 강제로 확인 시켜준다.
Private / public, save 는 다음과 같이 선언할 수 있다.
INTEGER, DIMENSION(:), ALLOCATABLE, SAVE, PRIVATE :: ivari_name
또는
implicit none
private
save
integer .....
real*8 .......
