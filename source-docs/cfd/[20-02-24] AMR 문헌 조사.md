1. AMR 기법들
1970’s
Babuska and Rheinboldt, AMR에 대한 FEM에서 첫번째 작업
수치해석의 질을 향상시키는 방법, 오차를 낮추는 방법
= h-adaptivity : 메쉬를 더 심어서 오차를 줄이기
= p-adaptivity : 차수가 더 높은 수치기법을 사용하기
= r-adaptivity : 메쉬와 기법의 정확성은 그대로하고, 포인터를 컴퓨터 에러가 감소하는 방향으로 재배치한다.
고려해야할 문제
= load balancing (로드 밸런싱) -> Dynamic load balancing
= flux corrections (플럭스 수집)
= exchange of solution information between blocks (블록간 통신)
  블록을 감싸고 있는 ghost cell 도입 (ghostcell overlapping)
= refinement criteria (refine 기준)
  밀도 구배, 속도 구배, 와류 존재

1.1. block-structured AMR (SAMR)
- Berger and Oliger, 1984
- 과거 30년동안 개발되어 온 기법.
- 모든 코드들은 큰-스케일의 parallel 시스템을 커버할 수 있다.
- C/C++ 또는 Fortran 으로 작성되었다.
- 로드 밸런싱 중에 space filling curves (SFCs, 한선 그리기) 를 사용할 수 있다.
- 1998년에 시작된 BoxLib 와 Chombo 는 일반적인 SAMR 프레임워크이다. Patch-based AMR 적용
- 또다른 일반적인 SAMR은 Cactus 이다.
- FLASH, PARAMESH
- Charm++
1.2. 종류
1) Block-based
고정된 블록으로 메쉬가 나눠진다. 블록마다 특정조건이 성립할 때 refine 된다. 상대적으로 간단한 데이터 구조를 가진다. 그러나 초과적인 refine 메쉬로 이끌 수 있다.
2) Cell-based
각 셀에서 refine 된다.
3) Patch-based
직사각형 patch 형태로 refine 된다. 구조적 mesh를 가지고, 초과적 refine 이 되지 않는다. 그러나 알고리즘이 복잡함.
2. 오픈소스들
2.1. Paramesh (Parallel Adaptive Mesh Refinement)
-  NASA Goddard Space Flight Center 에서 개발
- 오픈소스, 포트란 based, octree-based AMR, 더 이상 개발이 진행되지 않음.
- uniform refinement blocks에 기초한 라이브러리 [MacNeice et al., 2000]
- Multigrid & explicit 알고리즘 포함
- multi-dimensional
- Structured grid blocks
- 휴대성
- User Tunable 로드 밸런싱
- I/O to chombo HDF5 파일
2.2. BoxLib (AmrLib) (AMReX)
- C++/포트란90 가 합쳐진 코드
- 새로워진 BoxLib의 브랜치는 순수한 포트란90으로 만들어졌지만 현재는 오직 non-subcycling 알고리즘만 서포트하고있음.
- explicit & implicit grid-based 오퍼레이션을 각각 서포트한다. 뿐만 아니라 계층적 adaptive mesh에 입자들도 포함됨.
- cell-based & node-based 데이터에 대한 싱글 레벨, 멀티 레벨 멀티그리드도 포함됨.
- C++과 포트란90 버전 각각에 대한 기본적인 parallel 추출은 MultiFab 이고, 그것은 한 레벨에서 블록의 모음에 대한 데이터를 유지함.
- MultiFab은 다수의 FABs (포트란 어레이 박스들)으로 구성됨; 각 FAB은 싱글 블록에 대한 데이터 어레이임.
- 노드 사이에 분포된 MultiFab을 구성하는 FAB; 각 refinement 레벨에서 MultiFab들은 독립적으로 분포함.
- 각 노드들은 meta-data를 유지하고 이것은 지오메트리와 MultiFab들의 프로세서 할당량을 완벽히 구체화시키는 것을 필요로 함.
- J. Bell et al., 50,000 LOC [Rendleman et al., 2000]
- multigrid & explicit 알고리즘 구현
2.3. Chombo
- Lawrence Berkeley National Laboratory 에서 개발
- 오픈소스, FVM/FEM에서 가능, patch-based AMR
- 박스들의 모음을 BoxLayout 이라고 부른다.
- P. Colella et al. 에 의해 재디자인 되었음.
- Multigrid & explicit 알고리즘 구현
- 몇몇 embedded boundary 지원

- Mapped 지오메트리, 몇몇 embedded boundary 지원

3. 용어들
-Octree Construction
= Cell : 나눠진 도메인의 가장 작은 단위
= mesh/grid : 나눠진 도메인을 설명하는 일반적인 방법
= block : 직사각형 모양의 셀의 모음
= patch : 동일한 크기의 연속 셀 모음
= active cells : 오퍼레이터가 블록으로 적용될 때 업데이트 되는 블록에서의 셀
= guard cells : 오퍼레이터에 의해 업데이트는 안되지만 오퍼레이터의 계산을 위해 필요한 활성화 셀 주위의 셀의 무리
= level : 같은 셀 사이즈를 가지는 블록들
= framework : 코드의 인프라구조 뼈대
= component : 코드 내에 조직화된 독립적 기능
4. 오픈폼 AMR
- dynamicRefineFvMesh, hexRef8, refinementHistory 로 구성
- 클래스 dynamicRefineFvMesh 는 메쉬를 유지하면서 mesh refinement를 쓰도록 불러온다. (refinement-engine)
- hexRef8 은 셀을 자를 때 사용한다. (mesh-cutter)
- refinementHistory 는 refinement의 히스토리를 유지한다 (refinement-tree)
1) Refinement-engine
dynamicRefineFvMesh의 다이어그램은 다음과 같다. 그것은 primitiveMesh의 서브클래쓰이다.
Polyhedral 셀과 FVM을 다룹니다.
클래스 primitiveMesh는 메쉬의 primitive 형태를 나타낸다. 그것은 영구적인 메쉬 데이터를 나타내고, 메쉬와 지오메트리 데이터의 연결 구조를 만들어내는 함수이다. 셀 중심, 셀 볼륨, 표면 센터, 표면적을 계산한다. 연결 구조는 예를들면; 셀과 엣지에 속하는 것들 또는 연결된 셀들. 포인트와 셀을 얻기 위해 Virtual function인 points, faces, faceOwner, faceNeighbour 을 primitiveMesh 에서 제공한다.
polyMesh는 일반적 polyhedral 셀의 메쉬를 다룬다. 여기서는 전에 다뤘던 points, faces, faceOwner, faceNeighbour를 다룬다. 면과 셀들은 주어진 케이스 디렉토리에서 파일로부터 읽어질 수 있다.
클래스 fvMesh는 유한 체적 차분을 다룬다. 면적 운동 플럭스, 면적 벡터, 면적 크기를 위한 다른 필드를 추가한다.
클래스 dynamicFvMesh는 변화하는 메쉬의 지오메트리와 토폴로지를 다룬다. Virtual function 인 update()는 건설하고 파괴하는 펑션이다.
FvMesh는 hexRef8로 불리는 다른 클래스를 사용하고 이것은 meshCutter 변수에 저장된다.
셀을 쪼개기 위한 가장 효과적인 방법을 찾기 위해 hessian을 계산한다. Hessian은 2차 미분 함수에 대한 정사각행렬이다. 그것은 얼마나 휘고 구부러졌는지 알 수 있다.
decompositionMethod 클래스를 사용함으로써 메쉬의 재분배를 다룰 수 있다. 그래서 이것은 모든 셀의 리스트를 얻고 각 프로세서로 뿌려준다.
2) Mesh-cutter
클래스 hexRef8은 메쉬 커터로 불린다. 그리고 hexahedral 셀을 8개 서브셀로 쪼갠다.
클래스 polyTopoChange는 수정된 포인트, 페이스, 그리고 셀을 제거하거나 추가하는 펑션이다.
setRefinement()는 셀의 리스트와 polyTopoChange 를 input으로써 취하고, 그러고나서 polyTopoChange 속으로 이들의 셀들 변화를 집어넣는다.
hexRef8은 refinementHistory를 포함하고 있는데, 이것은 메쉬에 대한 refinement-tree 타입이다. hexRef8이 메쉬를 자르는 엔진이기 때문에, 이것은 일반적으로 8개의 서브셀로 나눠지는것에 제한적이다.
4) Refinement-tree
클래스 refinementHistory는 지금까지 행해졌던 refinement의 역사를 보관하는 클래스이다.
이 클래스는 히스토리를 업데이트하고 다른 프로세스에 히스토리를 재분포시킨다.
이 클래스는 셀의 라벨과 그들의 refine 히스토리만 저장하고, 포인트와 다른 값들은 저장하지 않는다.
