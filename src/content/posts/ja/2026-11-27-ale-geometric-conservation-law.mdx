## 何もしていないのに密度が変わった

密度1の流体が速度1で一様に流れています。格子ノードだけを正弦波状に揺らします。物理的には何も起きないはずです。ところが2秒後、密度は最大1.07%ずれていました。奇妙な点はもう一つあります。全質量は小数点以下15桁まで正確に1でした。

この記事ではこの矛盾を解きます。原因は幾何学的保存則(GCL、Geometric Conservation Law — 格子運動そのものが偽の生成項を作らないための条件)です。読み終えれば、ALEコードで面速度をどう計算すべきかを一行でまとめられます。

2020年2月、流体–構造連成(FSI、Fluid–Structure Interaction)を勉強していたとき、手法を四つに整理しました。ALE、AMI、キメラ(overset)、埋め込み境界法(IBM)です。このうち前の三つは格子が動きます。格子が動いた瞬間、GCLの問題がついてきます。

## 問題:FSIで移動形状を扱う四つの方法

構造物が動くと流体領域の形が変わります。対応は大きく二つに分かれます。格子が動きに追従するか、格子は固定して境界を埋め込むかです。

- **ALE(Arbitrary Lagrangian–Eulerian)**:格子ノードが任意の速度 $\mathbf{w}$ で動きます。$\mathbf{w}=0$ ならオイラー、$\mathbf{w}=\mathbf{u}$ ならラグランジュです。壁近くのノードは構造物に追従し、内部のノードは滑らかに補間します。
- **AMI(Arbitrary Mesh Interface)**:回転領域と静止領域が接する面で、一致しない面同士を重なり面積で補間します。各領域の内部は剛体として動きます。
- **キメラ(overset)**:物体を囲む格子が背景格子の上を丸ごと移動します。重なった領域で値を補間してやり取りします。
- **IBM(Immersed Boundary Method)**:格子は固定です。境界は力の項として埋め込みます。詳しくは[埋め込み境界法のdirect forcingとデルタカーネル](/ja/posts/2026-08-03-immersed-boundary-direct-forcing-delta-kernel/)で扱いました。

前の三つはいずれも、セル体積が時間とともに変わるか、セルが移動します。セル境界が動くと、フラックスに格子速度が入ります。その格子速度の計算方法に落とし穴があります。

下のシミュレーションで、セル一つの二つの面を実際に揺らしてみましょう。

黄色のバーは、面が1ステップで実際に動いた距離です。紫のバーは、フラックスが仮定した距離 $w\,\Delta t$ です。`w(t_n)` を選んで Δt を大きくすると二本のバーがずれ、下のグラフの二つの体積曲線が離れていきます。その比の分だけ密度の表示が1から外れます。`swept (GCL)` に切り替えると曲線が重なり、密度は正確に1に戻ります。

## 原因:体積変化とフラックスが別々の時計を見ている

移動する検査体積 $V(t)$ に対する保存式は次の通りです。

$$
\frac{d}{dt}\int_{V(t)} \rho \, dV + \oint_{S(t)} \rho\,(\mathbf{u}-\mathbf{w})\cdot\mathbf{n}\, dS = 0
$$

$\rho$ は密度、$\mathbf{u}$ は流体速度、$\mathbf{w}$ は面速度、$\mathbf{n}$ は外向き法線です。

ここに $\rho = $ 定数、$\mathbf{u} = $ 定数を入れます。一様流は厳密解です。$\mathbf{u}$ の項は閉曲面積分なので消えます。残るのは次の式です。

$$
\frac{dV}{dt} = \oint_{S(t)} \mathbf{w}\cdot\mathbf{n}\, dS
$$

これがGCLです。セル体積の変化率は、面が掃いた体積に等しくなければならない、という意味です。連続レベルでは当たり前の恒等式です。

問題は離散化の後に起きます。1次元有限体積法で、セル $i$ の更新は次のようになります。

$$
(\rho V)_i^{n+1} = (\rho V)_i^{n} - \Delta t\,\big[F_{i+1/2} - F_{i-1/2}\big], \quad F = \rho\,(u - w)
$$

$V_i^{n+1}$ は新しいノード位置から幾何学的に計算します。一方、フラックスの中の $w$ は別に計算します。一様解が残るには次が必要です。

$$
V_i^{n+1} - V_i^{n} = \Delta t\,\big(w_{i+1/2} - w_{i-1/2}\big)
$$

これが**離散GCL**です。左辺は幾何、右辺はフラックスから来ます。両者が違えば、その差だけ $\rho$ が生まれたり消えたりします。

よくある間違いは、$w$ をノード運動の解析的微分 $dx/dt$ の $t^n$ での値にすることです。これは左リーマン和になります。ノードが等速で動かない限り、実際の移動距離と $O(\Delta t^2)$ だけずれます。毎ステップ、この誤差がセル間に再配分されます。

では全質量はなぜ保存されるのでしょうか。フラックス形式だからです。セル $i$ から出る $F_{i+1/2}$ は、そのままセル $i+1$ に入ります。足し合わせると内部フラックスはすべて打ち消し合います。つまり質量が**どこへ行くか**は間違えていても、**いくらか**は合っています。保存形スキームがGCLを自動的に保証しない理由です。

## 解決:面が実際に掃いた体積をそのまま使う

処方は単純です。面速度を次のように定義します。

$$
w_{i+1/2} = \frac{x_{i+1/2}^{n+1} - x_{i+1/2}^{n}}{\Delta t}
$$

すると離散GCLは恒等式になります。ノード運動がどれほど複雑でも関係ありません。2次元・3次元では、各面が掃いた体積 $\delta V_f$ を幾何学的に計算し、$\dot{V}_f = \delta V_f / \Delta t$ をフラックスに使います。OpenFOAMの `meshPhi` がまさにこの量です。

中点時刻 $t^{n+1/2}$ での解析的な $w$ を使うとどうでしょうか。中点則なので、1ステップあたりの誤差は $O(\Delta t^3)$ に下がります。しかしゼロではありません。多段階時間積分や回転格子では、この残差が蓄積します。

## コード:三種類の面速度で一様流を2秒間流す

周期境界の1次元領域 $[0,1]$ にセルを64個置きます。ノードは $x = \xi + a\sin(2\pi\xi)\sin(2\pi t/T)$ で揺らします。流体速度は1、初期密度は1です。1次風上フラックスで2秒進めた後、$\max|\rho-1|$ を測ります。

```python
import math

def node_pos(xi, t, amp, period):
    # 基準格子 xi を正弦波状に揺らす(両端ノードは固定)
    return xi + amp*math.sin(2*math.pi*xi)*math.sin(2*math.pi*t/period)

def node_speed(xi, t, amp, period):
    # ノード位置の解析的な時間微分 dx/dt
    return amp*math.sin(2*math.pi*xi)*math.cos(2*math.pi*t/period)*2*math.pi/period

def ale_uniform_test(n, dt, mode, amp=0.05, period=0.25, t_end=2.0, v=1.0):
    xi = [j/n for j in range(n+1)]
    x = [node_pos(s, 0.0, amp, period) for s in xi]
    rho = [1.0]*n                         # 一様密度から出発
    steps = int(round(t_end/dt))
    for k in range(steps):
        t0, t1 = k*dt, (k+1)*dt
        x_new = [node_pos(s, t1, amp, period) for s in xi]
        if mode == "w(t_n)":
            w = [node_speed(s, t0, amp, period) for s in xi]
        elif mode == "w(t_n+1/2)":
            w = [node_speed(s, t0 + 0.5*dt, amp, period) for s in xi]
        else:                              # GCL: 面が実際に掃いた距離 / dt
            w = [(b - a)/dt for a, b in zip(x, x_new)]
        f = []
        for j in range(n):                 # 面 j: セル j-1 | セル j(周期境界)
            rel = v - w[j]                 # 面を通過する相対速度
            f.append(rel*(rho[j-1] if rel > 0 else rho[j]))
        f.append(f[0])
        mass = [rho[i]*(x[i+1]-x[i]) - dt*(f[i+1]-f[i]) for i in range(n)]
        x = x_new
        rho = [mass[i]/(x[i+1]-x[i]) for i in range(n)]
    total = sum(rho[i]*(x[i+1]-x[i]) for i in range(n))
    return max(abs(r - 1.0) for r in rho), total

n = 64
print(f"N = {n}, amp = 0.05, period = 0.25, t_end = 2.0, v = 1")
print(f"{'dt':>6} | {'w(t_n)':>9} | {'w(t_n+1/2)':>10} | {'GCL':>8} | total mass, w(t_n)")
for dt in [4e-3, 2e-3, 1e-3, 5e-4]:
    e = {m: ale_uniform_test(n, dt, m) for m in ["w(t_n)", "w(t_n+1/2)", "GCL"]}
    print(f"{dt:6.0e} | {e['w(t_n)'][0]:9.2e} | {e['w(t_n+1/2)'][0]:10.2e} | "
          f"{e['GCL'][0]:8.1e} | {e['w(t_n)'][1]:.15f}")
print()
print("amp scan at dt = 1e-3: max|rho-1|, w(t_n) | GCL")
for amp in [0.01, 0.025, 0.05, 0.1]:
    a = ale_uniform_test(n, 1e-3, "w(t_n)", amp=amp)[0]
    g = ale_uniform_test(n, 1e-3, "GCL", amp=amp)[0]
    print(f"  amp = {amp:5.3f}: {a:.2e} | {g:.1e}")
```

## 出力を読む:1.07%、1.8e-5、そして2e-15

**Δtに対する次数。** `w(t_n)` の列は Δt を半分にするたびにおよそ半分になります(1.07e-2 → 6.09e-3 → 3.20e-3 → 1.64e-3)。1次です。中点の列は約4倍ずつ減ります(1.82e-5 → 5.09e-6 → 1.34e-6 → 3.42e-7)。2次です。スキーム自体は空間1次風上なのに、この誤差は純粋に時間方向の幾何の不一致から来ています。

**GCLの列はゼロです。** 2e-15は丸め誤差です。Δt や振幅をどう選んでも、一様流は保たれます。これがGCLの定義です。精度の改善ではなく、恒等式が成り立つということです。

**質量の列。** `w(t_n)` でさえ全質量は1.000000000000000です。質量の合計チェックではこのバグを捕まえられないということです。ALEコードを検証するとき、質量収支より先に**一様流保存テスト**を回すべき理由です。

**振幅スキャン。** 振幅が2倍になると、誤差は2倍より少し大きくなります(0.05 → 0.1で3.20e-3 → 1.51e-2)。面速度が振幅に比例し、大振幅ではセル体積変化が非線形になるためです。FSIでは構造変位が大きいほど、GCL違反の代償が高くつきます。

## 実際のFSIコードでの現れ方

1次元のおもちゃでは1%は小さく見えます。実際の計算では、症状はもっと巧妙です。

- **偽の圧力振動。** 圧縮性ソルバーでは密度誤差はそのまま圧力誤差です。振動する翼の周りに、格子振動の周波数で圧力ノイズが生じます。空力弾性解析では、このノイズが構造へフィードバックされます。
- **安定性の喪失。** GCLを満たさない高次時間積分は、線形安定限界が狭まることがあります。固定格子でうまく回っていたBDF2が、移動格子で発散することがあります。
- **非圧縮性ソルバーの連続式残差。** 圧力補正は体積フラックスの和から計算されます。面フラックスに幾何学的な $\dot V_f$ を使わないと、圧力方程式のソース項に格子運動のノイズが混ざります。

格子品質も併せて見る必要があります。大変位でセルが歪むと非直交補正が必要になります。これは[非直交拡散フラックス補正](/ja/posts/2026-07-01-non-orthogonal-diffusion-correction/)で扱いました。IBMは格子が固定なのでGCLの問題はありません。その代わり、境界付近の精度と質量漏れで代償を払います。四つの手法の選択は、結局このコストをどこで払うかの問題です。

## 移動格子ソルバーを新しく書くとき、最初に回すテスト

一様流だけを入れて、格子を激しく揺らします。境界は周期条件にします。数周期後に $\max|\rho-1|$ か $\max|\mathbf{u}-\mathbf{u}_0|$ を出力します。1e-14付近でなければ、面速度の計算が幾何とずれています。このテストは5分で書けます。翼振動の解析を1週間回した後に圧力ノイズの原因を探すより、はるかに安上がりです。
