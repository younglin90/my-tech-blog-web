## 인터랙티브 시각화 — **원칙: 매 포스트마다 주제에 맞춰 즉석에서 custom 컴포넌트를 직접 작성한다**

> **기본 경로 (권장)**: 오늘 포스트 내용에 딱 맞는 React 컴포넌트 1~2개를 `src/components/post-viz/{오늘 slug}/{ComponentName}.tsx`에 **새로 작성**하고, MDX frontmatter 바로 아래 `import { ComponentName } from '@/components/post-viz/{slug}/ComponentName'`로 가져와 본문에서 사용한다. 이렇게 하면 포스트가 수만 개가 되어도 중복 없이 주제별 고유 시각화가 확보된다.
>
> **Custom 작성 규칙**:
> - 파일 첫 줄 `'use client'`
> - 외부 라이브러리 추가 금지 (react, Canvas/SVG API, 프로젝트 내 `@/lib/*`만 사용)
> - 내부 state + 슬라이더/버튼으로 파라미터 조작 UI 구성
> - 애니메이션은 `requestAnimationFrame` + cleanup in `useEffect` — 60fps 유지
> - 컴포넌트 이름은 주제 반영 + 전역 유일 (PascalCase)
> - gridSize 100 이하 권장, 복잡한 3D/WebGL은 지양
>
> ---
>
> ## Fallback: pre-built 7개 컴포넌트 (특수 경우만)
>
> 아래 7개는 **매핑 표와 정확히 일치하는 주제**이고 custom 제작이 과한 경우에만 선택한다. 사용 빈도 불균형:
> - **미사용(우선 후보)**: `BoundaryCondition`, `NumericalScheme`, `PressureContour`
> - 1회 사용: `NumericalDungeon`, `MachArchitect`
> - 2회 사용: `StreamLine`, `VelocityField` (반복 편중 위험)
>
> `{USED_VIZ_COMPONENTS}`에 이미 나열된 컴포넌트는 **가급적 피하고**, 미사용·덜 쓰인 것을 먼저 고려하라.

---

### 1. BoundaryCondition — 경계조건 인터랙티브 설명 (미사용, 최우선 후보)
```mdx
<BoundaryCondition type="inlet" interactive={true} />
```
- type: 'inlet' | 'outlet' | 'wall' | 'symmetry'
- interactive: boolean (기본 true)

### 2. NumericalScheme — 수치 스텐실 시각화 (미사용, 최우선 후보)
```mdx
<NumericalScheme scheme="upwind" order={1} />
```
- scheme: 'upwind' | 'central' | 'quick'
- order: 1 또는 2

### 3. PressureContour — 압력 등고선 (미사용, 최우선 후보)
```mdx
<PressureContour levels={10} colormap="viridis" />
```
- levels: number (기본 10)
- colormap: 'viridis' | 'plasma' | 'coolwarm' (기본 'viridis')

### 4. NumericalDungeon — 수치해석 인터랙티브 게임형 탐험 (props 없음)
```mdx
<NumericalDungeon />
```

### 5. MachArchitect — 마하수/압축성 유동 시각화 (props 없음)
```mdx
<MachArchitect />
```

### 6. StreamLine — 유선 애니메이션
```mdx
<StreamLine particles={50} speed={1.0} obstacle="cylinder" />
```
- particles: number (기본 50)
- speed: 0.1~2.0 (기본 1.0)
- obstacle: 'none' | 'cylinder' | 'airfoil'

### 7. VelocityField — 속도장 벡터
```mdx
<VelocityField reynolds={100} animated={true} gridSize={20} />
```
- reynolds: number (기본 100)
- animated: boolean (기본 true)
- gridSize: number (기본 20)

## 주제 → 컴포넌트 매핑 표 (오늘 포스트 주제와 가장 잘 맞는 것을 고를 것)

| 포스트 주제 키워드 | 우선 컴포넌트 |
|---|---|
| 경계조건, inlet/outlet/wall, symmetry, ghost cell, 격자 경계처리 | **BoundaryCondition** |
| 수치 스텐실, upwind / central / QUICK, 차분 스킴 비교, 고차 정확도 | **NumericalScheme** |
| 압력 해법, Rhie-Chow, 체커보드, Poisson 방정식, SIMPLE 수렴 | **PressureContour** |
| 수치해석 개념 교육, 직관 훈련, 학습자 설명 | **NumericalDungeon** |
| 압축성, Mach 수, 충격파, de Laval 노즐, shock tube | **MachArchitect** |
| 실린더 뒤 와열, 박리, 카르만 거리, 입자 추적, 유선 가시화 | **StreamLine** |
| Reynolds, 속도장 벡터, 천이, 격자 해상도, 점성계수 효과 | **VelocityField** |

## 선택 규칙 (순차 적용)

1. **매핑 일치**: 오늘 포스트 주제가 위 매핑 표의 한 행에 명확히 해당하면 그 컴포넌트를 **우선** 선택.
2. **중복 회피**: 선택한 컴포넌트가 `{USED_VIZ_COMPONENTS}`에 이미 있으면 — 미사용 3종(BoundaryCondition, NumericalScheme, PressureContour) 중 주제와 가장 가까운 것으로 대체.
3. **주제 애매**: 매핑에 정확히 해당하지 않으면 → 미사용 3종 중 하나를 선택한다.
4. **최소 1개 미사용 보장**: 포스트에 viz를 2개 넣을 때, **적어도 1개는 `{USED_VIZ_COMPONENTS}`에 없는 컴포넌트**여야 한다.

## 삽입 규칙

1. **필수**: 포스트당 1~2개 반드시 삽입. **0개는 실패 조건 → 재작성.**
2. **안내 문장**: 삽입 직전 1문장으로 독자에게 안내 ("아래 시뮬레이션에서 직접 파라미터를 조작해보자.")
3. **관찰 포인트**: 삽입 직후 1~2문장으로 "이 값에서 저 값으로 바꾸면 ~한 현상이 관찰된다" 식 안내
4. **props 타입 준수**: 위 각 컴포넌트 시그니처를 정확히 지킬 것. 존재하지 않는 prop 사용 금지.
